# docs-ds

Docusaurus site for the Data Science team wiki and ds-cli guide. It replaces an earlier Next.js static-export site and is designed to end up on Snowpark Container Services with a Cortex Agent chat widget; until then it deploys as plain static files.

## Run locally

Requires Node.js 22 and npm.

```bash
npm ci
npm start
```

Open **http://localhost:3333/docs/**. Markdown and theme changes reload automatically.

To preview the production site with working local search:

```bash
npm run validate
npm run serve
```

Search is generated at build time; it is unavailable in development mode.

## What's included

- Separate autogenerated Wiki and Guide sidebars; new Markdown files appear automatically.
- Data Science colors and typography, square corners, active sidebar accents, and system-aware light/dark mode.
- Local full-text search, with no external search service.
- Plain Markdown support (`format: 'detect'`), frontmatter, tags, code highlighting, and an ADR starter template.
- Production build checks, a docs lint, GitLab and GitHub CI, nginx examples, and an unprivileged static-site container.
- Skills and a sync script that build the wiki out from real repositories instead of hand-copied content.

## How content gets here

The site is a shell that skills fill in. Nothing in `docs/` is copied from a repository by hand.

| Piece | Owner | Runs where |
| --- | --- | --- |
| Facts block on each project page, project index table, changelog activity block | `npm run sync` (`scripts/sync-projects.mjs`) | A machine with the team's repositories checked out; the list is in untracked `sync.config.local.json` |
| Project narrative, changelog entries, insights, ADRs, guide pages | Skills in `.claude/skills/` (`ds-wiki-project`, `ds-wiki-change`, `ds-wiki-insight`, `ds-wiki-adr`, `ds-guide-page`) | Wherever the source repository is |
| Hygiene: structure, policy, stale and stub pages, broken links | `npm run lint` (`scripts/lint-docs.mjs`) and the `ds-docs-audit` skill | Locally and in CI |

The sync only rewrites text between `<!-- sync:...:start -->` and `<!-- sync:...:end -->` markers. Skills and people own everything else. `CLAUDE.md` is the contract both follow.

### First-time setup

```bash
cp docs-policy.local.example.json docs-policy.local.json   # company name and internal hosts (gitignored)
cp sync.config.local.example.json sync.config.local.json   # repositories to sync (gitignored)
scripts/install-skills.sh --cortex                          # symlink skills into ~/.claude/skills and ~/.snowflake/cortex/skills
export DS_DOCS_PATH=$PWD                                    # lets the skills find this checkout from other repos
npm run sync && npm run lint
```

`docs-policy.json` carries the generic rules (private IPs, account locators, tokens, emails, allowed link hosts). The company name and internal hostnames belong only in the untracked local file, so they never appear in this repository, and both the lint and the sync fail if one slips through.

### Continuous integration

`.github/workflows/build.yml` runs `npm run validate` (lint, typecheck, build, build checks) on every push and pull request and uploads `build/`. `.gitlab-ci.yml` does the same for a GitLab shell runner that provides Node.js 22. Neither runs the sync; they build what is committed.

### Not yet migrated

The previous site's content repository (`ds-app`) was not available when this shell was built, so its project pages, insights, app catalog, ADR registry, exact CSS, and logo were not imported. Section pages carry an "Awaiting" note until a skill or an import replaces them. `static/img/ds-monogram.svg` is a temporary text monogram.

To import rather than rewrite: copy the ds-app `docs/wiki/` and `docs/guide/` trees over this one preserving frontmatter, or build against a sibling checkout with `DOCS_CONTENT_PATH=../ds-app/docs`. The `ds-changes` write paths (`docs/wiki/changelog.md`, `docs/wiki/projects/<name>.md`, `docs/wiki/insights/<slug>.md`, `docs/wiki/adr-index.md`) are unchanged; `ds-wiki-change` is its successor here.

## Configuration

Set environment variables in the shell or CI **before building**. `.env` files are not loaded automatically. Do not put credentials in Docusaurus configuration; generated assets are browser-visible.

| Variable | Default | Purpose |
| --- | --- | --- |
| `SITE_URL` | `https://analytics.example.com` | Placeholder public origin; set this for deployment |
| `SITE_BASE_URL` | `/docs/` | URL prefix, with leading/trailing `/` |
| `DOCS_CONTENT_PATH` | `docs` | Content source directory |
| `DOCS_EDIT_URL` | Unset | Enable edit links for the actual content repository |

The default keeps the `/docs/` path and uses an example domain. Set `SITE_URL` to the actual deployment origin. For a dedicated SPCS host, also build with `SITE_BASE_URL=/`.

## Deployment

`npm run validate` type-checks, builds, and verifies the main routes, local assets, and search index. Static output is in `build/`.

- [.gitlab-ci.yml](.gitlab-ci.yml) saves `build/` as an artifact. Replace `<docs-runner-tag>` with the tag of a shell runner that provides Node.js 22 before using the pipeline. This job does not publish to the live server.
- [deploy/nginx-existing.conf](deploy/nginx-existing.conf) is a fragment for the existing server's `/docs/` location. Adapt the example filesystem path and preserve the rest of the server config.
- [Dockerfile](Dockerfile) serves the build with nginx on port 8080. Default site path: `/docs/`; health endpoint: `/healthz`.

```bash
docker build -t docs-ds .
docker run --rm -p 8080:8080 docs-ds
```

For a dedicated host:

```bash
docker build \
  --build-arg SITE_URL=https://docs.example.com \
  --build-arg SITE_BASE_URL=/ \
  -t docs-ds .
```

See [Deploying this site](docs/guide/admin/deploying-this-site.md) for publishing layout and the remaining SPCS/Cortex integration work.
